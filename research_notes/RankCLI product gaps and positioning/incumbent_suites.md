# Incumbent SEO platforms and crawlers: developer-facing and AI-search offerings, prices and gaps (as of 2026-10-29)

Scope: Ahrefs, Semrush, Screaming Frog SEO Spider, Sitebulb, Lumar (DeepCrawl), Oncrawl, Botify, SE Ranking, Moz, Google (Search Console, Lighthouse, PageSpeed Insights, CrUX, Chrome DevTools MCP) and Bing Webmaster Tools, with brief notes on Conductor, BrightEdge and seoClarity. Method: seven parallel source sweeps on 2026-10-29 (vendor pricing pages, developer docs, changelogs, help centres, GitHub and npm registries, Search Central and Bing blogs, HN and dev.to, Trustpilot; G2/Capterra/Reddit via search snippets because those sites return 403 to fetchers), followed by direct re-verification of the Semrush pricing page, the G2 AEO category (403) and Lumar's agentic-readiness CLI. Conventions: every number carries a source URL; read date is 2026-10-29 unless the citation gives another date; facts older than 2026 carry their own date; "not stated" means the page was checked and is silent; "(search snippet)" marks text taken from a search engine's summary of a page that could not be opened. Nothing in the RankCLI repository was modified apart from creating this file.

## Key Question 1: What CLI, API, CI/CD integration, MCP server, agent skill or IDE integration does each incumbent ship as of October 2026, what launched in 2025-2026, and what does it cost?

### Takeaway
Every incumbent now has an MCP server or agent skill (Ahrefs Sep 2025, Semrush 2025-2026 with a Claude connector Aug 2026, Screaming Frog May 2026, Sitebulb Sep 2026, Chrome DevTools MCP Sep 2025), but none ships a CI gate with exit codes except Lumar Protect (enterprise, no public price) and Google's Lighthouse CI (10 fixed SEO checks, pinned to Lighthouse 12.x). The only CLI among the SaaS platforms is Screaming Frog's desktop CLI (£199/$279 per user per year, no documented exit codes, no REST API); Ahrefs, Semrush, Sitebulb, SE Ranking and Moz ship no CLI, and API access is gated to $129/mo (Ahrefs Lite) or custom-priced tiers (Semrush Advanced/Enterprise).

### Inferences
- The MCP wave is complete: by October 2026 every platform in scope (Ahrefs, Semrush, Screaming Frog, Sitebulb, Lumar, Oncrawl, Botify, SE Ranking, Moz, Conductor, BrightEdge, seoClarity) plus Chrome DevTools has an MCP server, so "has an MCP server" is table stakes, not a differentiator. - Only two incumbents give a developer a CI gate with a documented exit code: Lumar Protect (enterprise contract, cloud crawl of a staging host, `exit 1` in a reference shell script) and Lumar's brand-new free `agentic-readiness` CLI (19 checks, AI-agent legibility only, hosted checks for canonical/JSON-LD excluded). Lighthouse CI offers an exit code but on 10 fixed page-level SEO audits. Screaming Frog's CLI has no documented exit code.
- No incumbent CLI runs the full technical-SEO check set locally for free: Screaming Frog's CLI is paid per user (£199/$279), desktop-bound and licence-file gated; Ahrefs, Semrush, SE Ranking and Moz are API/MCP only, with API access starting at $129/mo (Ahrefs Lite), custom pricing (Semrush Advanced), $20/mo for 3,000 rows (Moz API) or included credits (SE Ranking Core $129/mo).
- The Lumar agentic-readiness launch (Oct 14-23 2026) is the clearest signal that an incumbent sees the developer CLI + exit code + preview-URL pattern as worth copying; it is narrow (19 checks, no SEO fundamentals) and unbranded on npm, which is a positioning window rather than a threat today.

### Inferences
- The incumbents' GEO investment is overwhelmingly on the demand side (simulate prompts, scrape answers, score share of voice), priced as add-ons from roughly $45-$99/mo. The supply side (is the site crawlable, renderable and citable by AI engines) is thin: Semrush and Ahrefs have robots-based bot-access checks, Lumar has a GEO report pack and the new 19-check CLI, and Screaming Frog, Sitebulb, Moz and SE Ranking have nothing. That is the space a site-side readiness audit occupies with little overlap.
- Nobody generates or validates llms.txt as a product feature; Semrush flags its absence, Lighthouse 13.2+ validates its link format, and Google says Search ignores it. A tool that checks llms.txt should frame it as "for AI agents and non-Google engines", citing the Google guide, to avoid being contradicted by Google's own docs.
- Engine coverage is unstable: Moz and SE Ranking both dropped Perplexity on or about Oct 26 2026, and a Trustpilot buyer complained of paying for Perplexity tracking that "was never delivered". Claims about which engines a tool tracks should carry a date.
- Google's two public positions (Search ignores llms.txt; Chrome's Lighthouse audits it under "agentic browsing") mean "AI readiness" has two audiences, Google's AI features (plain SEO plus no restrictive snippet controls) and third-party agents/LLM crawlers (robots access, rendering without JS, llms.txt, WebMCP/ARD), and a readiness checker needs to say which one each check serves.

### Inferences
- The developer need is documented in the developers' own words (noindex shipped via a forgotten env var, canonical to staging, "invisible to Search Console for weeks", "SEO regressions are invisible at deploy time"), and their current answer is a hand-rolled Playwright/JSDOM script with `sys.exit(1)`, or Lighthouse CI with its 10 SEO checks. The incumbents' responses are overlays and tickets aimed at marketers ("No devs needed"), which is the opposite of a PR.
- The desktop crawlers' developer pain is structural, not fixable by a feature: per-user licences (Screaming Frog, Sitebulb), Java/RAM footprints, no Linux (Sitebulb) or a licence file plus Xvfb for headless Linux (Screaming Frog), and no REST API. The SaaS platforms' pain is price and gating: API starts at $129/mo (Ahrefs), custom (Semrush), or row-metered (Moz), and none exposes a crawl in a way a CI job can gate on.
- "Fix generation" in incumbents means edge injection (Botify PageWorkers, Ahrefs Patches) that leaves the repository wrong; a code-level auto-fix PR is a different category of fix with no incumbent equivalent found.
- The dev-first entrant list (LintPage, Seoscan, xeolint, geo-lint, seo-guardian, seo-agent, seocli, Lumar agentic-readiness) shows the pattern is being rediscovered monthly in 2026; most are single-author tools with 0-2 HN points, so the category is forming but has no established leader. The incumbent with the closest move is Lumar (free CLI + MCP, Oct 2026) and Sitebulb's "Release Check" skill (Aug 2026), both narrow.

### Inferences
- The analyst-recognised categories are all brand-visibility monitoring (prompt simulation and citation scraping), not site-side readiness. A CLI that checks whether a site is crawlable and citable by AI engines does not fit Gartner's definition ("monitor and analyze a brand's presence in generative answers") and would be judged on the wrong criteria there.
- The realistic near-term listing path is G2 "SEO Tools" plus G2 "Answer Engine Optimization (AEO)" (both have Grids), with "AI Search Visibility Optimization Tools" as a third once it becomes report-ready. Each needs 10+ recent approved reviews; a Leader badge additionally needs Market Presence (employee counts, review volume), which favours incumbents, so "High Performer" is the attainable quadrant for a small vendor.
- A new "Developer SEO" G2 category would need 10 competing products; the dev-first entrants listed in Key Question 3 (LintPage, Seoscan, xeolint, geo-lint, seo-guardian, seo-agent, seocli, Seomator, Unlighthouse, Lighthouse CI, SEODeploy) are enough names to argue the count, but most have no G2 presence or reviews, so the category would start without a Grid.
- Google's "still SEO" framing and Bing's "GEO tooling" framing both favour a tool that bundles classic technical SEO with AI-search checks rather than one that splits them.
