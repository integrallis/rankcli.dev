# RankCLI first-run product audit (outside-in, 2026-10-29)

Environment for every measurement below: Linux (Pop!_OS kernel 7.0.11), Node v25.5.0, npm 11.8.0, Claude Code 2.1.312, run from a scratch directory outside the repository on 2026-10-29. Package versions resolved by `@latest` today: `@rankcli/cli@0.0.50` (published 2026-10-14), `@rankcli/mcp-server@0.0.23` (published 2026-10-14). Raw outputs (console reports, JSON reports, fetched HTML) are saved under `/tmp/claude-1000/-home-bsb-Code-products-rankcli-dev/fda27b37-e636-4809-a5e6-96a1f408fcce/scratchpad/rankcli-audit/`. "Measured" means I ran the exact command quoted; "judgement" marks my own reading of a result.

## Key question 1: First run (install, run, output, scores, false positives, other commands)

### Takeaway
Install and first audit are fast (cold install 5.9 s, one-page audit about 10 s wall), the JSON output is clean and CI-friendly with documented exit codes 0-3, but the console report hides 80 percent of findings behind a "Top 10" with no flag to show the rest, three commands print "coming soon", three different commands give three different scores (85 / 93 / 100) for the same URL in the same minute, and the issue list is padded by duplicate codes and by checks that fire on every site regardless of content (Bing Places, AMP, "review content without video", "no YouTube channel").

### Cited Findings

- Cold install into an empty npm cache: `npm_config_cache=<empty dir> npx -y @rankcli/cli@latest --version` took 5.87 s wall, 286 MB peak RSS; the resulting cache is 130 MB on disk, `node_modules` 68 MB with 126 packages. Largest dependencies pulled in: `openai` 20 MB, `rxjs` 12 MB, `@supabase` 10 MB, `@anthropic-ai` 4 MB, `@rankcli` 4 MB — [npm @rankcli/cli](https://www.npmjs.com/package/@rankcli/cli)
- Warm `npx -y @rankcli/cli@latest --help`: 3.80 s wall, 182 MB RSS — same source.
- Registry metadata: `@rankcli/cli@0.0.50`, 49 versions since 2026-01-31, unpacked 1.1 MB / 16 files, 11 dependencies (`@rankcli/agent-runtime`, `@supabase/supabase-js`, `chalk`, `commander`, `conf`, `ora`, `inquirer`, `axios`, `cheerio`, `open`, `table`), MIT, no `repository` field — [registry.npmjs.org/@rankcli/cli](https://registry.npmjs.org/@rankcli/cli)

Findings that look like false positives or are unexplained (measured from the saved JSON, verified against the raw HTML with curl):
- docs.astro.build: the root URL answers HTTP 200 with an 80-byte body `<!DOCTYPE html><meta http-equiv="refresh" content="0;url=/en/getting-started/">` (same for curl and a Chrome user agent; the real page at /en/getting-started/ is 149 KB). RankCLI audits the stub without following the meta refresh, which produces all 7 errors (`TITLE_MISSING`, `H1_MISSING`, `VIEWPORT_MISSING`, `NO_INTERNAL_LINKS`, `CLIENT_SIDE_RENDERING`, `EMPTY_BODY_CONTENT`, `RESPONSIVE_NO_VIEWPORT`) and the 57/100. The same 57 appears in the repo's VERIFIED-NUMBERS.md as a comparison figure (see key question 6) — [docs.astro.build](https://docs.astro.build); judgement: a developer who owns that site would call every one of those errors a false positive, since Google follows meta refresh.
- nextjs.org `KEYWORD_STUFFING` (warning): details `{"keywords":["next"],"densities":[{"word":"next","density":4.16}]}`; the brand name on the brand's homepage is counted as stuffing at a 3 percent threshold — measured; judgement: false positive.
- nextjs.org `HEADING_SKIP` `{"from":2,"to":4}` is a true positive: the source has 1 h1, 9 h2, 1 h4 and no h3 — measured with `grep -oiE '<h[1-6][ >]'`. rankcli.dev produced no heading-skip finding today (source has h1, h2, h3, h4) — measured.
- nextjs.org `ROBOTS_TXT_MISSING` is a true positive: https://nextjs.org/robots.txt returns 404 (sitemap.xml and llms.txt return 200) — measured.
- `AI_KEY_CONTENT_NOT_IN_HTML` (warning) fired on nextjs.org and on sive.rs with `hasFirstParagraph:false`; sive.rs is plain server-rendered HTML with 1287 words, so "key content missing from initial HTML" is wrong there — measured; judgement: false positive on static sites.
- `CONTENT_AUTHORITY_IMBALANCE` (warning): "Site has ~1144 pages but limited backlink signals. Content is unlikely to rank." on nextjs.org, and "~1608 pages" on sive.rs. The tool has no backlink data source (none is declared in `--help` or the README) — measured; judgement: unsupported claim presented as a warning.
- `BING_PLACES_MISSING` ("Your site appears to have a physical location") fired on all four sites, including rankcli.dev where the same run also reported `ADDRESS_NOT_DETECTED` and `PHONE_NOT_DETECTED` — measured; contradiction within one report.
- `BING_NOT_VERIFIED` (warning, category ai-readiness) fired on all four sites including nextjs.org; its detection is meta tag / DNS TXT / BingSiteAuth.xml only, so sites verified through Search Console import or a CNAME are flagged anyway — measured; judgement: unverifiable from outside, should not be a warning.
- `REVIEW_NO_VIDEO` ("Product review or comparison content lacks video demonstrations") fired on all four sites; `AMP_MISSING` on three; `NO_YOUTUBE_PRESENCE` and `NO_EMBEDDED_SOCIAL` on rankcli.dev and nextjs.org — measured; judgement: AMP has been irrelevant to ranking since 2021 and the others are not SEO defects.
- `NEW_SITE_STRATEGY` on rankcli.dev: `estimatedAge: 35` days, while the npm package has existed since 2026-01-31 and the public repos since 2026-09-03 — measured; wrong age.
- `HTML_TOO_LARGE` (warning) at a 100 KB threshold flagged rankcli.dev at 105 KB and nextjs.org at 254 KB — measured; judgement: an aggressive threshold for modern sites.
- sive.rs `FAQ_SCHEMA_MISSING` (warning) lists the "questions" `["Me in 10 minutes?", "What am I doing now?", "How to Live (2021)"]` (a book title); `NO_KEYWORDS_IN_TITLE` (warning) recommends adding "book" to the title "Derek Sivers" with top keywords `["book","books","sive","four","com"]`; `COMMERCIAL_NO_CTA` fired on a personal site with `pageType: "mixed"` — measured.
- Duplicate codes for one condition inflate the counts: on docs.astro.build the missing viewport is reported three times (`VIEWPORT_MISSING` error, `HTML_NO_VIEWPORT` warning, `RESPONSIVE_NO_VIEWPORT` error), and there are pairs for schema (`SCHEMA_MISSING`/`SCHEMA_ORG_MISSING`), apple touch icon, llms.txt (`LLMS_TXT_MISSING`/`AI_NO_LLMS_TXT`), organization schema, lang attribute, Bing verification (`BING_VERIFICATION_MISSING` notice + `BING_NOT_VERIFIED` warning), IndexNow (`INDEXNOW_NOT_IMPLEMENTED`/`BING_NO_INDEXNOW`), sitemap (`SITEMAP_MISSING`/`BING_SITEMAP_MISSING`), H1 (`H1_MISSING`/`NO_VISIBLE_HEADLINE`), CSR (four codes), and internal links (three codes). On rankcli.dev the absence of testimonials is reported under six codes (`NO_SOCIAL_PROOF`, `BOFU_NO_SOCIAL_PROOF`, `AI_NO_TESTIMONIALS`, `AI_NO_REVIEW_INTEGRATION`, `AI_NO_REVIEW_PLATFORMS`, `AI_WEAK_REVIEW_ECOSYSTEM`), four of them warnings — measured from the JSON.
- Score inconsistency across commands for the same URL within minutes: `audit` 85/100 (50 issues); `apply -u https://rankcli.dev --dry-run` printed "Running full audit (200+ checks)… Score: 93/100, Issues found: 15, Generated 0 actionable fix(es)"; `fix -u https://rankcli.dev --dry-run` printed "0 fixable issue(s) found (quick scan: 100/100 …) ✅ No issues found! Your site looks great." — measured (both run in an empty, non-git directory, framework "Unknown").

Other commands (measured, no login, no AI key in the environment):
- `--help` lists 19 commands (login, logout, whoami, init, analyze, audit, apply, fix, geo, keywords, content, intent, competitors, track, report, watch, setup, gsc-setup, alerts). Three are stubs that exit 0: `report` prints "Report generation coming soon...", `watch` prints "Watch mode coming soon...", `competitors -d squirrelscan.com` prints "Competitor analysis coming soon..." — measured.

- `geo -u https://rankcli.dev`: works anonymously; "GEO Score: 72/100", lists allowed AI crawlers, "Server-side rendered", LLM-friendliness bars, two recommendations — measured.
- `content -u https://rankcli.dev`: works; "Readability Score: 68/100", Flesch 51.5, but "Paragraphs: 1" for 1287 words — measured.

- `setup --github-action --url https://rankcli.dev` in an empty directory warns "No package.json or index.html found" but still writes `.github/workflows/seo.yml` (weekly cron, `npm install -g @rankcli/cli`, `rankcli audit … --output json`, files a GitHub issue via `actions/github-script`, uploads the JSON artifact, no gates by default) and `.github/SEO_SETUP.md`; the generated workflow does not use the published `integrallis/rankcli-action` — measured.
- `alerts --list`: "Run `rankcli login` first, then manage alerts at https://rankcli.dev/account?tab=notifications" — measured. `login --token rk_bogus_123`: "Invalid API key format. Keys should start with "rankcli_"", exit 1 — measured. `whoami`: "Not logged in", exit 0 — measured.
- `analyze` in an empty directory reports "Content files: 0, Has README: ❌ …" and suggests adding a README — measured.

### Inferences
- A developer's first impression is good (fast, scored, colourful) but the second look is where trust is lost: the top-10 cap hides the long tail, the long tail is where the duplicate and generic checks live, and `fix` telling the same developer "No issues found! Your site looks great" right after `audit` reported 13 warnings reads as the tool contradicting itself.
- The issue count ("Issues found: 50") is the number most people will quote, and it is inflated by code duplication and by checks that fire unconditionally; the "280+ checks" headline and the padded counts reinforce each other in the wrong direction.
- The docs.astro.build result shows the crawler does not follow `meta refresh` and treats a 200 stub as the page; any site with a root redirect implemented that way (common on docs sites with locale prefixes) will get a catastrophic score.
- `rankcli.config.json` existing but being ignored by `audit` means `init` currently has no payoff for the audit path.

### Gaps
- I did not run `--ai` (no provider key was supplied and the task said not to spend money), so AI analysis quality and the Apple Intelligence path are unmeasured.
- Whether the anonymous CLI sends any telemetry or audit data to RankCLI servers was not verified with a network trace; the docs claim nothing is sent.
- I could not test `fix` against a real framework project (the task forbids running it against the repository), so whether it ever generates a fix is unmeasured; against an empty directory it generated zero.

## Key question 2: Expectations check (what a 2026 CLI developer looks for)

### Takeaway
Of the thirteen features a developer expects, only CI gating (`--fail-on`, `--min-score`) and exit-code documentation exist; a config file is written by `init` but neither documented nor read; ignore rules, baseline/diff, per-category budgets, SARIF/JUnit, PR annotations, JS rendering, CWV field data, sitemap-driven crawl, authenticated pages, local dist audits, hreflang, llms.txt generation and a `--ci` mode are absent, and the /docs page documents fewer exit codes than the CLI itself.

### Cited Findings
- Config file: `rankcli init` writes `rankcli.config.json` (measured, see KQ1) but the npm README has 0 mentions of "rankclirc", "config file" or "rankcli.json", and the /docs page mentions no config file at all — [npm README](https://www.npmjs.com/package/@rankcli/cli); [rankcli.dev/docs](https://rankcli.dev/docs). The only config affordance documented is `RANKCLI_CONFIG_DIR` ("Store login/config here instead of the per-user config dir") — [npm README](https://www.npmjs.com/package/@rankcli/cli)
- Ignore rules: none in the CLI (`audit --help` has no ignore/exclude/disable flag, measured); the docs describe a dashboard "Mark as Ignored" action only — [rankcli.dev/docs](https://rankcli.dev/docs)
- Baseline / diff mode: not mentioned in README or docs (0 hits for "baseline", "diff"); the `seo-ci-gate` skill opens with "## 1. Establish the baseline first" but that is a manual step for the agent — [SKILL.md](https://github.com/integrallis/rankcli-mcp-server/blob/main/skills/seo-ci-gate/SKILL.md)
- Budgets / thresholds: only the global `--fail-on <error|warning|notice>` and `--min-score <n>`; no per-category thresholds (0 hits for "budget") — [audit --help, measured]; [npm README](https://www.npmjs.com/package/@rankcli/cli)
- SARIF / JUnit: none (0 hits in README; output formats are `json, console`); RankCLI's own comparison pages state "no SARIF" for RankCLI — [rankcli.dev/compare/squirrelscan](https://rankcli.dev/compare/squirrelscan)
- PR annotations: none; the GitHub Action posts a PR comment and a job summary ("reports it on the pull request and in the job summary") — [rankcli-action README](https://github.com/integrallis/rankcli-action)
- JS rendering of SPAs: none; the comparison page says "RankCLI has no headless browser, so it audits pages as served, and its performance checks are heuristic" — [rankcli.dev/compare/lighthouse-ci](https://rankcli.dev/compare/lighthouse-ci). CSR detection exists and penalises the SPA (animerm.ai 51/100 with `REACT_CSR_DETECTED`), measured.
- Core Web Vitals field data: none; the homepage says "Core Web Vitals estimation from HTML" and the MCP tool is "Estimate LCP, CLS, INP, TTFB from HTML" — [rankcli.dev](https://rankcli.dev); [MCP README](https://github.com/integrallis/rankcli-mcp-server)
- Sitemap-driven crawl: not documented ("Sitemap appears only as a crawlability check and in auto-fixes") — [rankcli.dev/docs](https://rankcli.dev/docs); crawl discovery is link-based from the homepage, which is why docs.astro.build yielded 1 page (measured).
- Authenticated pages: no `--header`, `--cookie` or auth flag (0 hits; `audit --help` measured).
- Local dist-folder audit: the docs say `audit` runs "on a URL or local project", but `audit --help` has only `--url`, and `audit` without `--url` exits 2 — [rankcli.dev/docs](https://rankcli.dev/docs); measured. `analyze` inspects the working directory only superficially (README/sitemap/robots presence), measured.
- hreflang: 0 mentions in README or docs, and no hreflang code appeared in any of the five audits — measured; whether a check exists internally is unknown.
- llms.txt generation: detection only (`LLMS_TXT_MISSING` and `AI_NO_LLMS_TXT` fired on sive.rs, docs.astro.build, animerm.ai); no generator command or MCP tool (the MCP server generates robots.txt, schema and security headers but not llms.txt) — measured tools/list; [MCP README](https://github.com/integrallis/rankcli-mcp-server)
- `--ci` mode: none; CI behaviour is the two gate flags plus the Action's `fail-on-errors` / `score-threshold` inputs — [rankcli-action README](https://github.com/integrallis/rankcli-action)
- Exit codes: documented in `audit --help` and the npm README as 0 / 1 / 2 / 3 with meanings, and behave as documented (measured); the /docs page, per the fetched content, documents only exit 1 for the gate flags — [rankcli.dev/docs](https://rankcli.dev/docs); [npm README](https://www.npmjs.com/package/@rankcli/cli)
- `.rankclirc`: does not exist (0 hits anywhere).

### Inferences
- The CI story is "exit code + JSON", which is enough for a shell gate but not for the GitHub Code Scanning / SARIF, JUnit test-report or PR-annotation integrations developers already use with ESLint, Lighthouse CI and Semgrep; without a baseline or ignore file, a team cannot adopt the gate on an existing site because the first run fails on findings they cannot suppress.
- The docs page and the README disagree on basic facts (exit codes, "local project"), which is the kind of thing a developer checks before trusting the tool in a pipeline.

### Gaps
- The /docs content was read through a fetch tool that summarises; the exact wording around exit codes on the page could not be quoted verbatim.
- I did not test the Action itself in a workflow run (no repo to push to under the constraints), so PR-comment formatting is from its README only.

## Key question 3: Agent path (MCP server, Claude Code plugin, framework plugins)

### Takeaway
The agent path is the most polished part of the product: the MCP server starts via npx and lists 15 tools, the hosted free endpoint answers, the Claude Code plugin and `npx skills add` both install first time, and the three framework plugins have followable READMEs — but the plugins are seven-check validators plus sitemap/robots generators, not the 280-check engine, and the CLI's npm README advertises a different, stale MCP tool list.

### Cited Findings
- `npx -y @rankcli/mcp-server@latest` 0.0.23 starts on stdio ("RankCLI MCP Server running on stdio"), negotiates protocol 2025-06-18 and `tools/list` returns 15 tools: `seo_analyze, seo_geo_check, seo_robots_ai, seo_generate_robots, seo_core_web_vitals, seo_structured_data, seo_generate_schema, seo_security_headers, seo_generate_security_headers, seo_images, seo_internal_links, seo_mobile, seo_ai_crawlers, rankcli_connect, rankcli_disconnect`. The analysis tools take `html` / `robotsTxt` / `headers` parameters (the host must fetch the page); `url` is contextual — measured; matches the README table — [MCP README](https://github.com/integrallis/rankcli-mcp-server)
- Hosted free endpoint `POST https://mcp.rankcli.dev/mcp/free` answers `initialize` with server `rankcli 0.0.23` (HTTP 200, SSE framing); `https://mcp.rankcli.dev/mcp` without a key returns `{"error":{"code":-32600,"message":"Missing API key. Get one at https://rankcli.dev"}}` — measured.
- The GitHub README's hosted endpoint is `https://rankcli-audit-worker.fly.dev/mcp` while the npm README's is `https://mcp.rankcli.dev/mcp`; both answer HTTP 200 — [GitHub README](https://github.com/integrallis/rankcli-mcp-server); [npm README](https://www.npmjs.com/package/@rankcli/mcp-server)

  - `astro-rankcli`: "Works with Astro 3 through 7. On `astro build` it writes `sitemap.xml` and `robots.txt` into the output, unless `public/` already provides them. ### Inferences
- A developer who follows the MCP README gets working tools, but a developer who reads the CLI README first expects `seo_audit` with URL fetching and finds it is a paid hosted feature; the README mismatch is the first "bait" moment on the agent path.
- The framework plugins would be more honestly described as "SEO lint + sitemap/robots for your build" than as RankCLI integrations; a developer who installs one expecting 280 checks gets seven.
- The marketplace install clones over SSH; a developer without GitHub SSH keys configured may hit a clone failure on the first command (not tested here).

### Gaps
- I did not test the `.mcpb` Claude Desktop package, Cursor or VS Code one-click links.
- I did not exercise the plugins in a real Astro/Vite/Next build; their behaviour is taken from their READMEs.

## Key question 4: Public footprint (npm, GitHub, Marketplace, plugin directory, source)

### Takeaway
