## Critical — fix before the next paid customer

### 1. Worker secret is compiled into the public frontend [verified]
- `.github/workflows/deploy.yml:185` sets `VITE_AUDIT_WORKER_SECRET: ${{ secrets.AUDIT_WORKER_SECRET }}`, and `packages/saas/src/hooks/useProjects.ts:407` sends it from the browser. Any `VITE_*` variable ships in the JS bundle.
- The same value is Fly's `WORKER_SECRET` and Supabase's `AUDIT_WORKER_SECRET`. Anyone holding it can:
  - list every customer's in-flight jobs (`GET /jobs`, `audit-worker/src/index.ts:291`);
  - spend RankCLI's OpenAI, Brave and Serper keys (`/keywords`, `/competitive-search`);
  - overwrite any audit's results (`/audit`);
  - make `send-audit-email` email any customer.
- **Complication:** `deploy-saas.yml` builds without the variable, so the frontend falls back to `'dev-secret'`. Paid deep audits then 401 silently and sit in `pending`.
- **Action:** rotate the secret now. Move the browser→worker call behind an edge function that authenticates the user and holds the secret server-side.

### 2. GitHub App can be aimed at repos the user doesn't own [verified, partially fixed]
- `create-seo-pr` now requires an owner, but that doesn't close the hole.
- Owners can still set `projects.github_installation_id` and `github_repo_url` to anything:
  - the projects UPDATE RLS policy is `001_initial_schema.sql:377`;
  - `GitHubCallbackPage.tsx:106` writes the installation id from a URL query parameter;
  - `connect-github-repo/index.ts:86` resolves an installation for any `owner/repo`.
- **Action:**
  1. Revoke column UPDATE on those two columns from `authenticated`.
  2. Set them only in `connect-github-repo`, after verifying through the user's GitHub OAuth token that the user can access the repo.

### 3. Other service-role functions trust IDs from the request body
These functions are public: `--no-verify-jwt` is set on every deploy (`deploy.yml:457`), and they check no caller.
- `run-audit`
- `local-seo`: a free LLM proxy running on the project owner's decrypted BYOK key.
- `sync-gsc-metrics`: returns the owner's Google Search Console data.
- `sync-threat-hashes`

**Action:** apply the same service-key-or-owner check as `create-seo-pr`. Longer term, stop deploying everything with `--no-verify-jwt`; list the few functions that really are public (the Stripe and GitHub webhooks, free-audit).

### 4. Three tables have no RLS
- `ai_visibility_checks` (migration 024), `url_comparisons` (025) and `chatgpt_checks` (023) are readable, writable and deletable with the anon key.
- `check-ai-visibility` and `compare-urls` rate-limit by counting rows in those tables, so deleting your own rows resets the limit. That opens unlimited 4-provider LLM spend.
- **Action:** enable RLS, add owner-read policies, and do writes through the service role only.

### 5. `rankcli audit` can never fail a CI pipeline [verified]
- There is no `--fail-on` or threshold flag (`cli/src/index.ts:56-66`).
- Every error path returns normally. The only `process.exit` in `cli/src` is in `alerts.ts:158`.
- For a product whose pitch is "SEO meets CI/CD", this is the product bug. Add `--fail-on error|warning` and `--min-score N` with non-zero exits, plus a test that asserts the exit code.

### 6. The health score rewards broken sites
- `agent-runtime/src/audit/engine.ts:109` sets `validateStatus: () => true`, and the status code is never checked. `:161` and `:418` hard-code `200`.
- Results:
  - An unreachable site scores **91**.
  - An HTTP 500 page with a title and an H1 scores 70, with no status issue.
  - `noindex` (meta tag or `X-Robots-Tag`) is only a `notice` (`audit/types.ts:194`), and the header is never read.
- So a GitHub Action with `score-threshold: 80` passes while production is down.

### 7. Premium checks never reach paying users, and the protection is bypassable
- **The ship bug:** `cli/package.json:33-35`. `build:wasm` runs `cp -r pkg ../wasm` into a `wasm/` directory that already exists, so the fresh build lands in `wasm/pkg/`. The stale committed WASM from Feb 2026 is what gets published. `native-release.yml:161-173` has the same bug.
- **The bypass:**
  - the entitlement check trusts `planId` in the user-writable local config (`audit.ts:299-318`);
  - the decrypt passphrase sits in plaintext in the published `dist/index.js`;
  - the WASM exports `get_decrypted_code()`.
- **Do not fix the copy bug alone.** It would publish the premium code in extractable form. Decide first whether premium checks run server-side (the audit-worker already runs them) or whether client-side obfuscation is acceptable.

## High

### Billing and tiers
- **Lifetime-deal buyers pay and never get access.**
  - `stripe-webhook/index.ts:130-139` writes `status: "lifetime"`, which the CHECK constraint forbids, and the error is unchecked.
  - `auth.admin.getUserByEmail` doesn't exist in supabase-js v2.
  - The refund path calls an `exec_sql` RPC that no migration defines.
- **Annual and founding subscribers are treated as unknown tiers.** `validate-api-key` returns 403 "API access requires a paid subscription" for `pro_annual`, `agency_annual` and `pro_founding`. Tier logic keys on bare `plan_id` strings in:
  - `validate-api-key/index.ts:13-18`
  - `local-seo:23`
  - `create-seo-pr:22`
  - the audit-worker MCP
- **The audit worker compares a plan UUID to plan names** (`audit-worker/src/index.ts:473-486, 537-540`). Every paid user gets the fallback limits: 5 domains/month and weekly audits.
- **Webhook errors are swallowed as 200** (`stripe-webhook:170-190`), so a paying customer can silently end up on `plan_id: null`. `subscription.updated` never re-derives the plan, and `cancel_at_period_end` cancels immediately.
- **The founding offer's 100-seat / 90-day cap is never enforced at checkout.**

### Security
- **SSRF.** There is no private-IP or redirect guard anywhere URLs are fetched.
  - Unauthenticated routes: `/mcp/free` (`mcp-server/src/server.ts:20`), `free-audit` → `/audit/quick`, and `compare-urls`.
  - Body readback: `seo_robots_check` returns 2 KB of the body after following redirects, so it can read Fly `.internal` services.
- **One click hands over your API key.** `mcp-connect-claim` mints a key for any pending `connectId`, and `ConnectPage.tsx:17-30` claims on page load. A victim who opens an attacker's `/connect?id=` link gives the attacker their `rankcli_` key.
- **Open email relay.** `send-free-audit-report` sends to any address, with no auth, no rate limit, and unescaped HTML.
- **SECURITY DEFINER functions are executable by anon** with no ownership check and no `search_path`: `get_audit_trend`, `get_metrics_trend`, `correlate_seo_changes`, `check_audit_schedule`, `update_audit_schedule` (migrations 020 and 20250225).

### The CI/CD product surface
- **The GitHub Action can't be used.**
  - `action.yml` points at a gitignored `dist/`, and the documented `uses:` repos return 404.
  - DocsPage uses `fail-on-errors`, but the input is named `fail-on-error`.
- **The Action's `create-pr` never creates a PR.** No branch or commit is ever made (`runner.ts:77-130`), and the failure is swallowed.
- **The workflow that `rankcli setup --github-action` generates fails on every run.** `fix --auto --output json` prints nothing, and the next step runs `JSON.parse('')`.
- **API-key auth in CI silently downgrades paid users** to 100 checks. `login` short-circuits when `RANKCLI_API_KEY` is set (`auth.ts:104-110`).
- **AI-visibility failures look like "not mentioned".** Every `!response.ok` returns `mentioned:false` with no error (`check-ai-visibility:248-363`, `audit-worker:1414-1512`).
  - `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY` and `PERPLEXITY_API_KEY` are set by no deploy pipeline.
  - The OpenAI calls send `max_tokens` and `temperature` to a GPT-5.6 model. If that model rejects them, the headline metric reads 0–25% for everyone.
  - One live call per provider would settle it.

### Plugins
- **Vite:** sets every page's canonical to the homepage and overwrites the user's `robots.txt`.
- **Astro:** writes no files, and `failOnError` can't fire.
- **VS Code:** command IDs don't match the manifest, so every command is "not found".
- **Next:** JSON-LD helpers allow a `</script>` breakout (XSS).

## Web app and rankcli.dev's own SEO

The site doesn't pass the audit it sells. That's the most important marketing finding here.

- **No prerendering [verified live].**
  - With a GPTBot user agent, `/`, `/pricing`, `/blog` and a made-up URL all return byte-identical HTML: same title, and a canonical pointing at `https://rankcli.dev`.
  - GPTBot, ClaudeBot and PerplexityBot don't execute JS, so every page except the `<noscript>` blurb is invisible to AI search. That includes the blog post about fixing client-side rendering.
  - **Action:** prerender the public routes at build time: landing, pricing, docs, blog, tools, about. Either `vite-react-ssg` or a Playwright prerender step in `pnpm build` works. This is the single highest-leverage SEO/GEO change in the repo.
- **Broken canonicals.**
  - Even after JS runs, `/pricing`, `/about` and `/login` canonicalize to the homepage. Blog and tools pages carry two canonicals and two descriptions.
  - Cause: react-helmet-async can't remove the static tags in `index.html`, and `SEO.tsx` (with its `noindex` presets for login and dashboard) is imported nowhere. 23 of 31 pages have no Helmet at all.
  - **Action:** delete the static canonical and description from `index.html` and use `<SEO>` on every page.
- **Soft 404s.** There is no `*` route, so unknown URLs return 200 with a blank body. The `<noscript>` links point at `/tools`, `/tools/sitemap-validator` and `/tools/robots-checker`, none of which exist.
- **Testimonials look invented.** "TechFlow", "StartupX" and "ScaleUp Inc" were added the same day as the fake rating (`Testimonials.tsx:4-26`). Replace them with real quotes or remove the section.
- **The pricing page contradicts itself.**
  - The Free card says "all 280+ checks" and "GitHub auto-fix PRs"; the table below says 100 checks and no GitHub.
  - The check count reads 50+, 100, 200+ and 280+ in different places.
  - CLAUDE.md says Solo includes "GitHub connect"; the config and the table say it doesn't. Pick one source of truth.
- **The dashboard misreads tiers** (`useProjects.ts:325-369`).
  - `plan_id` is a UUID, so every paid plan gets the `?? 5` fallback.
  - LTD buyers (`plan_id: null`) get free-tier audits.
  - The domain-limit set is always empty because `projects[0]` indexes an object, not an array.
- **Agency features have no plan gate.** `AgencyPage`, client-report links and widget white-labelling are available to everyone. The white-label switch is a URL parameter (`WidgetPage.tsx:19,49`).
- **Performance.**
  - The main chunk is 1.7 MB (524 KB gzip). Every page is imported eagerly, and the full Prism grammar set rides along from `BlogPostPage`.
  - The hero text starts at `opacity: 0` inside `ScrollReveal`.
  - LCP measures 5.6 s on Slow 4G. Lazy-load routes and use `PrismLight`.
- **Sitemap.** `sitemap.xml` misses `/tools/ai-visibility`, `/about`, `/changelog` and others, includes `/login`, and every `lastmod` is 2026-01-24.
- **robots.txt.** Each AI bot gets its own `Allow: /` group. Under RFC 9309 that means those bots ignore the `*` group's Disallow rules for `/dashboard`, `/account` and `/auth`.
- **CI never runs the saas unit tests,** which is how the OOM went unnoticed. `pnpm lint` exits 2 because no ESLint config exists; `continue-on-error` hides it.
- **Smaller bugs.**
  - The profile "Save Changes" button is a 1-second sleep.
  - The committed `vite.config.js` shadows `vite.config.ts`.
  - OG images and manifest icons are missing.
  - `/login?redirect=` is ignored, so LTD checkout loses its place.

## Suggested order
1. **Rotate `AUDIT_WORKER_SECRET` now** and move browser→worker calls server-side.
2. **Push `5fdd756`, `9b147a6` and `218021f`.** Deploying applies the RLS migration.

4. **Fix tier resolution in one place.** Resolve plan UUID → `plan_id` → base tier (`pro_annual`/`pro_founding` → `pro`, LTD → its tier) in a shared helper, and use it in the webhook, `validate-api-key`, the worker and `useProjects`.

   - Add `--fail-on` / `--min-score` exit codes.
   - Score fetch failures, 5xx responses and `noindex` as errors.
   - Publish the GitHub Action from a public repo.
   - Fix `setup --github-action`.
6. **Prerender rankcli.dev and fix canonicals.** This is the dogfooding story, and it gives the Facebook, Reddit and HN posts something to point at.
7. **Decide the premium-check model** before fixing the WASM copy bug.
