## First comment (post it yourself, immediately)

I built RankCLI because every SEO tool I tried wanted a dashboard and a weekly email, and I
wanted a command that fails my build.

The write-up is the first run of something we now do every Monday: take the homepages of the
400 most popular npm packages, fetch each once as a browser and once as each of eleven
crawlers (Googlebot, bingbot, OAI-SearchBot, Claude-SearchBot, PerplexityBot, the user-triggered
fetchers, the training crawlers), plus robots.txt and the sitemap, and keep only what was
observed. 367 answered. Four in ten have no sitemap. Half publish an llms.txt, which no search
or answer engine reads. Three sites refuse Googlebot at the edge while a browser gets 200,
which robots.txt never shows you; that is why the audit fetches as each bot instead of
parsing a file.

The run also measured the tool: it printed 56 findings per site on average, and 30 of them
fired on six in ten of the best-built docs sites on the web. A notice every site gets carries
no information, so we removed 35 of them across two releases. The list of what went and why is
in the release notes.

What it is: `npx @rankcli/cli audit --url yoursite.com` runs 280+ checks and prints the
findings with the evidence behind each one. `--fail-on error` or `--fail-on "score<80"` gates
CI; there is a GitHub Action with baselines, an MCP server for Claude Code, Codex, Cursor and
ChatGPT, and plugins for Astro, Nuxt, Next.js and Vite. The engine and CLI are source-available
under FSL-1.1-MIT. The dataset, the list and the scripts are in the repo; a site can ask to be
left out.

Happy to answer anything about the methodology, and to hear which findings you disagree with:
that is how the 35 got removed.
