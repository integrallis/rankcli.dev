# The private beta, 2026-11

**The plan, as the founder set it on 2026-11-03:** 25 private invitations through GitHub, two
weeks of assessment, fill the gaps that surface, then the general launch. This file is the plan
for that phase and the record of it. It supersedes the ordering in `START-HERE.md` for the
duration; public distribution (the Nuxt modules directory, the Astro catalog, the GitHub
Marketplace listing, Product Hunt, the corpus write-up going anywhere public) waits until the
beta has been read.

## What the beta is for

The product is complete enough to audit the 400 most popular npm packages' sites and to run
in CI; what nobody has measured is twenty-five developers meeting it cold. The beta exists to
learn, before the general launch, three things a corpus run cannot:

1. **Where the first ten minutes break.** Install, first audit, the report, the first fix.
2. **Which findings they dispute.** A finding a developer argues with is either a false
   positive (fix the check) or a wording problem (fix the finding). Both are gaps.
3. **What they expected and did not find.** Asked twice by different people is a gap.

## The invitations

Twenty-five GitHub users, invited privately. The mechanism:

- A private repository, `integrallis/rankcli-beta`, holds the beta guide (`beta-repo/README.md`
  here, copied there), the feedback template, and GitHub Discussions turned on. Each invitee
  is added as a collaborator with read access; the invitation email GitHub sends is the
  invite. Nothing about the beta is public; the product repos stay as they are.
- `scripts/beta-invite.sh` creates the repository, pushes the guide and sends the
  invitations from `docs/launch/beta-invitees.txt` (one GitHub login per line; the file is
  gitignored because it is a list of people). The founder runs it; a session cannot create
  repositories or send invitations.
- Each invitee gets one personal line from the founder with the invitation, saying what the
  product is in a sentence and what we want from them: run it on a site they care about,
  tell us where it was wrong or unclear. No survey, no form.

Who to invite: developers who maintain a site with a build step, who would notice a wrong
finding and say so. Mixed stacks on purpose (Next.js, Astro, Nuxt, Vite, Rails, Hugo), a few
who run docs sites, a few agencies. Not SEO freelancers; the October signups showed what that
cohort does with the product (`ACTIVITY-LOG.md`, 2026-10-13 and 2026-10-15).

## The two weeks

The window starts the day the first invitation goes out and ends fourteen days later. During
it the founder and the sessions do three things and nothing else outreach-wise:

1. **Answer every Discussion and Issue within the day.** The answer is a fix, a doc change
   or a reason, each linked back from the thread.
2. **Pull the numbers twice a week** with `node scripts/beta-metrics.mjs <start-date>` and
   `node scripts/cf-traffic.mjs <start> <end>`, and write the two lines that matter into the
   tracker below.
3. **Keep the gap list** in this file current. Every gap has a source (who hit it), a decision
   (fix, document, decline, with the reason) and, when fixed, the PR.

## What is measured

Per invitee (the tracker), from the hosted product's tables and the beta repository:

| Signal | Source | Counts as |
|---|---|---|
| Accepted the invitation | GitHub (`gh api repos/integrallis/rankcli-beta/collaborators`) | reached |
| Signed up | `profiles.github_username` matches the login | activated 1 |
| Connected a repository or installed the Action | `github_installations`, or an Action run on their repo | activated 2 |
| Ran an audit (hosted or synced from the CLI) | `audits` by `triggered_by_user` | activated 3 |
| Opened an auto-fix PR | `github_prs` | activated 4 |
| Said something | Discussions, Issues, the personal reply | feedback |

Aggregate, the same script: signups per day, audits per day, API requests, auto-fix PRs, npm
downloads of the CLI and the plugins, the public repository's stars, clones and views. The
corpus-era baseline (2026-10-27 to 2026-11-02): `@rankcli/cli` 677 downloads a week (CI and
the corpus run included), 0 stars, 48 unique cloners.

## Exit criteria for the general launch

Not a date. The beta ends when all of these hold:

- Every disputed finding was fixed or answered in the finding's own text.
- Every gap hit by two or more people is closed or has a dated decision not to.
- Ten or more of the twenty-five reached "activated 3" (ran an audit on their own site).
- The first-ten-minutes path (install, audit, report, fix) was watched or narrated by at least
  five people and no longer breaks at the same place twice.
- `VERIFIED-NUMBERS.md` re-verified on the release that carries the fixes.
