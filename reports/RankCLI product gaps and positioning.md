# Own the deploy gate, open the source

RankCLI is not short of checks; it is short of trust and plumbing. The product already holds a position nobody else occupies, a free CLI, MCP server and GitHub Action that run a 280-check technical-SEO and AI-readiness audit locally and can open code-level fix pull requests, yet at **161 npm downloads a week** it sits fifth of eight developer-first rivals, **23x behind squirrelscan (3,784/wk)** and **26x behind GeoReady (4,201/wk on PyPI)**, with **one GitHub star across three public repos**, a homepage "GitHub" button that lands on a binaries-only repo, and two agent skills with **one install each** ([npm API](https://api.npmjs.org/downloads/point/last-week/@rankcli/cli); [skills.sh](https://www.skills.sh/integrallis/rankcli-mcp-server)). An outside-in first run explains the gap: the console hides 80 percent of findings behind a fixed top-10, three commands return three scores (85, 93, 100) for the same URL in the same minute, issue counts are padded by duplicate codes and checks that fire on every site, three commands print "coming soon", and the npm README contradicts the website on price, free tier and MCP tools ([npm README](https://www.npmjs.com/package/@rankcli/cli)). Every direct rival ships the CI plumbing RankCLI lacks (config file, baseline diff, SARIF or JUnit, per-category budgets, sitemap-seeded crawls, custom headers), and seven of them are on the GitHub Marketplace where RankCLI returns zero results ([Marketplace](https://github.com/marketplace?type=actions&query=rankcli)). Meanwhile the $1.8B GEO leaders sell daily prompt tracking to marketers at $29 to $999 a month and mention CI, pull requests or a CLI on none of eleven pricing pages, and the incumbent crawlers give developers no exit code, no PR surface and no local run; Lumar's free 19-check `agentic-readiness` CLI, shipped in October 2026, is the first incumbent to copy the developer pattern ([Lumar CLI](https://agentic-readiness.lumar.io/cli)). The head of the category is therefore open and will be decided by downloads and installs, not analyst grids: the pre-deploy gate for search and AI visibility that fails the build on the regressions developers actually suffer (a stray noindex, a canonical pointing at staging, a blocked OAI-SearchBot, a soft-404 llms.txt, JS-only navigation) and opens the fix as a PR. Taking it requires, in order, publishing the CLI source, repairing the first-run output, aligning the AI checks with the citation evidence, shipping the CI plumbing, and distributing through the channels that measurably move installs in this category (Marketplace, task-named skills, framework directories, incident-style data content, release cadence) rather than through launch posts.

## RankCLI is fifth of eight on downloads, and the first run spends the trust it earns

The download order among tools that do what RankCLI does is GeoReady (4,201/wk, PyPI), squirrelscan (3,784/wk), iannuttall/seo (2,279/wk), SEOmator (1,420/wk), RankCLI (161/wk), Crawlie (158/wk), geo-score (95/wk) and geolint (85/wk); RankCLI is last on stars among those with a public repository ([npm API](https://api.npmjs.org/downloads/point/last-week/squirrelscan); [pypistats](https://pypistats.org/api/packages/geo-optimizer-skill/recent)). The shape of RankCLI's own curve is telling: monthly downloads ran at 75 to 330 through most of 2026, spiked to **4,718 in September** and fell back to 416 in October, which is the signature of a launch burst plus CI and author traffic rather than organic pull ([npm API](https://api.npmjs.org/downloads/point/last-month/@rankcli/cli)). The agent-runtime package tracks the CLI count almost exactly (164/wk versus 161/wk), consistent with most downloads being the CLI's own dependency install ([npm API](https://api.npmjs.org/downloads/point/last-week/@rankcli/cli)).

The public footprint is where a sceptical developer stops. The `integrallis/rankcli-cli` repository, which the homepage's "GitHub" call to action links to, contains a README and a LICENSE and states plainly that the source "lives in the main (private) repo"; it has **0 stars**, the MCP server repo has 1 and the Action repo 0 ([rankcli-cli](https://github.com/integrallis/rankcli-cli); [rankcli.dev](https://rankcli.dev)). All 28 binary releases together total **192 asset downloads** and the Claude Desktop `.mcpb` on the latest release shows zero ([GitHub releases](https://github.com/integrallis/rankcli-cli/releases)). The Action carries the `branding` block the Marketplace requires but is not listed, and RankCLI's own comparison page says "Marketplace listing pending" ([compare/lighthouse-ci](https://rankcli.dev/compare/lighthouse-ci)). The plugin is absent from the 315-entry official Claude directory ([marketplace.json](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/.claude-plugin/marketplace.json)). The npm packages carry no `repository` field, and the three framework plugins point at `github.com/integrallis/rankcli.dev`, which returns 404 ([registry](https://registry.npmjs.org/astro-rankcli)). For a product whose pitch is "developer-first", an MIT tarball with no repository gets none of the benefits of open source (no stars, no dependents graph, no "Used by", no trending) while giving the code away anyway.

The first run itself starts well and then undermines itself. A cold `npx` install takes **5.9 seconds**, a one-page audit about 10 seconds wall, `-o json` prints one clean document on stdout with progress on stderr, and the documented exit codes 0 to 3 behave exactly as documented (measured on `@rankcli/cli@0.0.50` on 2026-10-29; [npm](https://www.npmjs.com/package/@rankcli/cli)). The second look is where trust leaks. The console report shows exactly ten issues and `audit --help` offers no `--all`, `--verbose` or `--limit`, so the other 40 findings on rankcli.dev, 50 on nextjs.org and 83 on docs.astro.build are invisible without JSON. Running `audit`, `apply --dry-run` and `fix --dry-run` against rankcli.dev within one minute returned **85/100 with 50 issues, 93/100 with 15 issues, and 100/100 with "No issues found! Your site looks great"**; a developer reads that as the tool contradicting itself. `report`, `watch` and `competitors` print "coming soon" and exit 0. `init -y` writes `rankcli.config.json`, but `audit` then still exits 2 asking for a URL, so the config file has no payoff. Every audit, including CI runs with `--fail-on`, ends in a boxed "rankcli login" upsell, and an unreachable host dumps a raw Node error object alongside exit 3. The /docs page documents a `-b/--browser` login flag the CLI does not have (it has `--no-browser`) and says `audit` runs "on a URL or local project" when no local option exists ([rankcli.dev/docs](https://rankcli.dev/docs)).

The issue count, the number most people will quote, is inflated in two ways. Duplicate codes report one condition several times: a missing viewport on docs.astro.build appears as `VIEWPORT_MISSING`, `HTML_NO_VIEWPORT` and `RESPONSIVE_NO_VIEWPORT`; missing llms.txt as `LLMS_TXT_MISSING` and `AI_NO_LLMS_TXT`; and the absence of testimonials on rankcli.dev under **six codes**, four of them warnings. Checks that fire regardless of content pad the rest: `BING_PLACES_MISSING` ("Your site appears to have a physical location") fired on all four test sites, including a report that also said `ADDRESS_NOT_DETECTED` and `PHONE_NOT_DETECTED`; `REVIEW_NO_VIDEO`, `AMP_MISSING`, `NO_YOUTUBE_PRESENCE` and `BING_NOT_VERIFIED` fired on sites where none is an SEO defect; `CONTENT_AUTHORITY_IMBALANCE` warns that content "is unlikely to rank" for lack of backlinks although the tool declares no backlink data source; `KEYWORD_STUFFING` flags the word "next" at 4.16 percent density on nextjs.org's own homepage; `AI_KEY_CONTENT_NOT_IN_HTML` fires on sive.rs, a hand-written server-rendered page; and `NEW_SITE_STRATEGY` estimates rankcli.dev's age at 35 days (measured; [sive.rs](https://sive.rs); [nextjs.org](https://nextjs.org)). The most consequential miss is structural: the crawler does not follow `<meta http-equiv="refresh">`, so docs.astro.build, whose root answers HTTP 200 with an 80-byte refresh stub, scores **57/100 with seven errors** that any Astro maintainer would call false, and that 57 sits in the repo's VERIFIED-NUMBERS.md as a public comparison figure ([docs.astro.build](https://docs.astro.build)). False positives at scale are a known maintenance burden in this category, not a user revolt: squirrelscan's maintainer found that 4 to 5 percent of audits in a 36,000-site batch were scoring a WAF challenge page as if it were the site ([squirrelscan #1253](https://github.com/squirrelscan/squirrelscan/issues/1253)); the difference is that RankCLI's sit on the first page of output.

The messaging compounds this. The npm README, which most developers read before the site, lists "Price: From $9/mo", "25+ frameworks", "Login to unlock all features" and an MCP tool set (`seo_audit`, `seo_robots_check`, `seo_compare`) three of which do not exist in the local server's `tools/list`; the website says free forever, 32 frameworks, 15 tools ([npm README](https://www.npmjs.com/package/@rankcli/cli); [MCP README](https://github.com/integrallis/rankcli-mcp-server)). The homepage hero says free without an account while its "How it works" step one is "Install and log in" ([rankcli.dev](https://rankcli.dev)). The homepage carries no customer logos, testimonials or benchmarks, and RankCLI's own audit of it reports `NO_SOCIAL_PROOF` and `AI_UNCITED_STATISTICS` as warnings. The compare pages are the strongest trust asset on the site precisely because they state RankCLI's limits plainly ("no headless browser", "no SARIF", "CLI source is not yet published") ([compare/squirrelscan](https://rankcli.dev/compare/squirrelscan)); the homepage carries none of that candour.

What RankCLI has that none of these has is also clear from the table. No rival's one-liner mentions pull requests: GeoReady's `geo fix` and Orino's `orino fix` write files into the working directory, and squirrelscan hands a "Copy fix prompt" to the coding agent, but none opens a code-level PR in the framework's idiom ([squirrelscan](https://github.com/squirrelscan/squirrelscan); [Orino](https://registry.npmjs.org/@bynaree%2Forino)). And the pricing shape, a free full-check CLI with a paid hosted weekly audit, is one no category leader uses. The problem is that a developer rarely gets far enough to discover any of it.

Release cadence is itself a distribution channel that RankCLI is not using. squirrelscan shipped **29 releases in the 16 days** to 2026-10-29, each with a prose changelog (a new Reliability category, a TLS rule, offline technology detection for Lovable, v0 and Supabase apps, an `--ephemeral` flag), and every release is a page that npm, GitHub and the Marketplace index ([squirrelscan releases](https://api.github.com/repos/squirrelscan/squirrelscan/releases)); GeoReady has shipped 90 PyPI releases since February ([PyPI](https://pypi.org/pypi/geo-optimizer-skill/json)). RankCLI's last release was 2026-10-14 and its changelog page lists six undated highlights ([rankcli.dev/changelog](https://rankcli.dev/changelog)).

Another developer wrote a JSDOM linter because "running Lighthouse in CI added 4 minutes to every build" and "for a CI pipeline that runs on every PR, you dont need comprehensive. You need fast and focused" ([dev.to](https://dev.to/robertatkinson3570/adding-seo-checks-to-cicd-without-slowing-down-your-pipeline-34dg)). RankCLI's lack of a headless browser is a real limit for SPAs, but three rivals name the same limit as a feature ("zero-browser", "No headless browser") ([seo-lint](https://github.com/marketplace/actions/seo-lint); [astro-seo-audit](https://registry.npmjs.org/astro-seo-audit)), and the fast-and-focused complaint suggests RankCLI should do the same.

## The $1.8B GEO leaders sell prompt tracking to marketers; nobody owns the pre-deploy gate

The analyst-recognised category is brand-visibility monitoring, and its economics are built on reselling engine queries. Profound raised a **$180M Series D at a $1.8B valuation** in September 2026, with cumulative funding above $335M and a claimed 1,000 enterprise brands ([Profound newsroom](https://www.tryprofound.com/newsroom/profound-raises-usd180m-series-d-at-usd1-8b-valuation-to-build-the-ai-platform-for-marketing-teams)). Below it, Peec AI sells 50 prompts across three models for $95/mo ([Peec pricing](https://peec.ai/pricing)), Otterly starts at $29/mo for 15 prompts and charges up to $439/mo just to add Claude ([Otterly pricing](https://otterly.ai/pricing)), Scrunch at $250 to $300/mo ([Scrunch pricing](https://scrunch.com/pricing)), AthenaHQ and Goodie at $295/mo ([AthenaHQ](https://www.athenahq.ai/pricing); [Goodie](https://higoodie.com/pricing)), Semrush's AI Visibility Toolkit at $99 per domain ([Semrush](https://www.semrush.com/pricing/ai/)) and Ahrefs Brand Radar from $50/mo for custom prompts or $199/mo for its index ([Ahrefs](https://ahrefs.com/brand-radar)). The unit of sale on every page is the daily-run prompt. The words "developer", "CI", "pull request" and "GitHub" appear on none of the eleven pricing pages read, and every buyer named is a marketing team or agency. G2's inclusion criteria for its AEO category are share-of-voice visibility, protection against inaccurate brand portrayals, transparency into why one brand is cited over another, and competitive benchmarking ([G2](https://company.g2.com/news/inside-the-2000-percent-growth-of-the-aeo-software-category-on-g2)); a site-side tool can honestly claim only the third. Gartner's first Market Guide defines the tools as "specialized solutions that monitor and analyze a brand's presence in generative answers" and sizes the market at **$481M in 2024 growing to $729M by 2031 at 5.7 percent**, a modest pool for the amount of venture money chasing it ([Gartner reprint](https://discover.siteimprove.com/hubfs/PDF%20Assets/Integration%20pages/Gartner_Market_Guide_2026_AEO.pdf)). RankCLI should not try to be judged there; it would be measured on criteria it cannot meet without reselling engine queries.

"Agent-native" is no longer a differentiator either. By October 2026 Profound, Otterly, Semrush, Ahrefs, SE Ranking, Rankscale, Goodie, Screaming Frog, Sitebulb, Lumar, Oncrawl, Botify, Moz, Conductor, BrightEdge and Chrome DevTools all have MCP servers, but nearly all are read-only, remote-only and gated behind a paid plan: Profound's requires sign-in with read-only analytics, Ahrefs forbids scripted use of its MCP and starts at $129/mo, Sitebulb's "doesn't start crawls" ([Ahrefs MCP docs](https://docs.ahrefs.com/mcp/docs/introduction.md); [Sitebulb MCP](https://sitebulb.com/mcp/)). When the leaders do "optimization", it arrives as a hosted layer that leaves the repository wrong: Scrunch's AXP generates an AI-friendly mirror of the site, Ahrefs "Patches" publish fixes live with "No devs needed", and Botify's PageWorkers inject changes through a JavaScript tag that "does not alter your website code" ([Ahrefs Site Audit](https://ahrefs.com/site-audit); [Botify PageWorkers](https://www.botify.com/platform/activation/pageworkers)).

The incumbent crawlers fail the developer test in structural ways. Screaming Frog's CLI costs **£199/$279 per user per year**, documents no exit codes anywhere, and a practitioner notes "There is no warning and no partial failure to alert you" ([Screaming Frog CLI guide](https://www.screamingfrog.co.uk/guides/command-line); [Chris Lever](https://chrisleverseo.com/forum/t/screaming-frog-seo-spider-cli.150/)); its founder confirms "We don't have an API, but as a desktop app we do have a CLI" ([SEO Spider 24](https://www.screamingfrog.co.uk/seo-spider-24/)). Sitebulb has had an open "Command line support" request since December 2020 and no Linux build ([Sitebulb feature request](https://features.sitebulb.com/suggestions/117004/command-line-support)). Semrush's only developer hand-off from Site Audit is a Trello integration ([Semrush](https://www.semrush.com/solutions/technical-seo/)). Lumar Protect is the one incumbent CI gate with a documented `exit 1`, and it sells by quote at a third-party-reported median of $57,250 a year ([automator-sdk ci.sh](https://raw.githubusercontent.com/deepcrawl/automator-sdk/master/ci.sh); [CostBench](https://costbench.com/software/seo-tools/lumar/)). Lighthouse CI is pinned to Lighthouse 12.6.1, so none of Lighthouse 13's agentic audits reach CI, its SEO category is 11 page-level audits, and its SEO documentation was last updated in 2019 ([LHCI releases](https://api.github.com/repos/GoogleChrome/lighthouse-ci/releases); [Lighthouse SEO docs](https://developer.chrome.com/docs/lighthouse/seo/)).

The warning shot is Lumar's `npx agentic-readiness`, released between 14 and 23 October 2026: 19 checks, exit codes 0/1/2, `--fail-on`, `--allow-private` for scanning "your own preview build", a GitHub Actions snippet, a free MCP endpoint and "No account, no key" ([Lumar CLI](https://agentic-readiness.lumar.io/cli)). It is narrow (agent legibility only, with canonical and JSON-LD checks held back in the hosted scanner), has no repository and no licence statement, but it proves an incumbent now sees the free CLI plus exit code plus preview URL pattern as worth copying. Below it, the same pattern is being rediscovered monthly by single-author tools (LintPage, Seoscan, xeolint, geo-lint, seo-guardian, seo-agent, SEO Desk) that each drew 0 to 2 points on Hacker News ([HN 47246980](https://news.ycombinator.com/item?id=47246980); [SEO Desk](https://github.com/marketplace/actions/seo-desk-audit)). No analyst or review site has a developer-SEO category, and the terms "developer SEO", "SEO CI/CD" and "SEO observability" have no analyst or press usage; the nearest G2 buckets are "SEO Tools" and "AEO", both of which need ten approved recent reviews for a Grid placement ([G2 methodology](https://documentation.g2.com/docs/research-scoring-methodologies)). Google's own May 2026 guide says "optimizing for generative AI search is optimizing for the search experience, and thus still SEO", and Bing calls its citation report "an early step toward Generative Engine Optimization (GEO) tooling" ([Google Search Central](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide); [Bing blog](https://blogs.bing.com/webmaster/February-2026/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview)); both favour one tool that runs classic technical SEO and AI-readiness in a single pass. The category head is unclaimed, and the leader will be decided by weekly downloads, skill installs and Marketplace presence, where squirrelscan (299 stars, 3,784/wk) is the only entrant with a visible lead.

## The citation evidence favours crawler access, indexing and freshness; llms.txt and schema are hygiene

Which checks RankCLI emphasises determines whether developers believe it, and the evidence ranks the site-side levers clearly. First is search-bot access by bot class. OpenAI documents that "Sites that are opted out of OAI-SearchBot will not be shown in ChatGPT search answers" while GPTBot is training-only and disallowing it does not affect search ([OpenAI bots](https://developers.openai.com/api/docs/bots)); Anthropic documents the same split between ClaudeBot (training) and Claude-SearchBot (search), with disabling the latter reducing "visibility and accuracy in user search results" ([Anthropic help](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler)). Cloudflare has changed its defaults twice: from 2025-07-01 new domains block known AI crawlers unless the owner opts out, and from 2026-09-15 training and agent crawlers are blocked by default on ad-bearing pages while search crawlers stay allowed; 17 percent of its sites enable some training block and under 1 percent block search bots ([Cloudflare 2025](https://blog.cloudflare.com/content-independence-day-no-ai-crawl-without-compensation/); [Cloudflare 2026](https://blog.cloudflare.com/accountable-mixed-use-ai-crawlers)). The only documented casualty is instructive: a law firm discovered on 2026-07-03 that "every major AI crawler was locked out" and "The block ran for seven months", and its advice is "assume you're blocked until you prove otherwise" ([Nacmias Law](https://nacmiaslaw.com/resources/articles/cloudflare-ai-crawler-block)). Because the block happens at the edge before robots.txt is read, the check that answers the developer's real question is a fetch as each bot's user agent with the status code reported, not a robots.txt parse.

Second is being indexed and ranking in classic search: **88.46 percent of ChatGPT citations come from the general search index** ([Ahrefs via SEJ](https://www.searchenginejournal.com/ai-search-myths-debunked-ahrefs-spa/584393/)), which makes every classic indexability regression an AI-visibility regression too. Third is freshness: cited URLs are 25.7 percent newer than organic results ([Ahrefs](https://ahrefs.com/blog/do-ai-assistants-prefer-to-cite-fresh-content/)), citation half-life is about 4.5 weeks ([Searchbloom summary](https://www.searchbloom.com/blog/citation-half-life/)), pages updated within three months averaged 6.0 ChatGPT citations against 3.6 for stale ones ([SE Ranking via SEJ](https://www.searchenginejournal.com/new-data-top-factors-influencing-chatgpt-citations/561954/)), and Bing tells publishers to pair accurate sitemap `lastmod` with IndexNow so AI systems reference the current version ([Bing blog](https://blogs.bing.com/webmaster/February-2026/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview)). Fourth is answer-shaped content: the Princeton GEO paper measured **+39.5 percent for adding quotations, +29.2 percent for statistics and −9.2 percent for keyword stuffing** ([arXiv 2311.09735](https://arxiv.org/html/2311.09735v2)), and a 193,507-answer observational study found 23 percent of cited pages open with a direct answer against 14 percent of retrieved-but-uncited ones, with tables carrying +69 percent odds ([TJ Digital via SEJ](https://www.searchenginejournal.com/ai-cited-pages-more-often-got-straight-to-the-answer/594781/)).

Two things RankCLI currently reports as warnings lack that support. For llms.txt, Ahrefs found that of 137,000 domains, 28 percent publish one, **97 percent of those files received zero requests in May 2026**, and about 1.1 percent of requests came from AI retrieval bots ([Ahrefs](https://ahrefs.com/blog/llmstxt-study/)); SE Ranking's 300,000-domain model found no effect on citations and improved when the variable was removed ([SE Ranking](https://seranking.com/blog/llms-txt/)); Google says the files "won't harm or help" and that "Google Search ignores them" ([Google Search Central](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)); a 17-day log study found "No verified AI or search crawler fetched llms.txt" while ClaudeBot fetched the sitemap 122 times ([pournasserian.com](https://pournasserian.com/writing/ai-friendly-website-2026)); and an SEO-plugin maintainer refused to ship it for a year as "essentially a placebo" ([craft-seomatic#1641](https://github.com/nystudio107/craft-seomatic/issues/1641)). The counter-signal is that Lighthouse 13.3.0 added an "Agentic Browsing" category with an llms.txt audit that checks existence, an H1, length and markdown links ([Lighthouse v13.3.0](https://github.com/GoogleChrome/lighthouse/releases/tag/v13.3.0)), that Anthropic, OpenAI, Perplexity, Stripe, Vercel and Supabase all publish one for their docs, and that the real demand in TanStack (+61 reactions), Docusaurus (+36) and Angular (+18) is for coding agents consuming documentation, not for search ([GitHub search](https://api.github.com/search/issues?q=%22llms.txt%22+is:issue+created:%3E2025-01-01&sort=reactions-%2B1&order=desc)). The honest framing is "a convention for agents and docs, audited by Lighthouse, read by no answer engine", and the only presence check worth running is one that verifies content type and content, because animerm.ai, the project's own test site, answers HTTP 200 with the SPA shell for both /llms.txt and /sitemap.xml, which a presence-only check misreports as passing ([animerm.ai](https://animerm.ai)). For structured data, Ahrefs' controlled test of 1,885 pages that added JSON-LD found citation changes of **+2.2 percent on ChatGPT, +2.4 percent on AI Mode and −4.6 percent on AI Overviews** against matched controls ([Ahrefs](https://ahrefs.com/blog/schema-ai-citations/)), while Bing says schema helps Copilot understand content ([Search Engine Roundtable](https://www.seroundtable.com/schema-llms-copilot-bing-microsoft-39093.html)); schema belongs in the technical-SEO half of the score, with FAQ schema in particular showing negative correlations in two datasets.

The most important finding for positioning comes from a rival. GeoReady's maintainer pre-registered a calibration study of its own rubric on 341 pages and found an **odds ratio of 0.962 per 10 score points (p = 0.717)**: no detectable association between its GEO score and whether Perplexity cited the domain ([GeoReady calibration](https://github.com/Auriti-Labs/geo-optimizer-skill/tree/main/research/calibration-2026-10)). No vendor has published evidence that any readiness score predicts citations, and buyers already say AI-visibility scores are "comparable to itself over time only if the model underneath held still, and it never does" ([Product Hunt, Lettertrace](https://www.producthunt.com/products/lettertrace)). That means RankCLI cannot honestly sell its AI Readiness number as a citation predictor, and neither can anyone else; what it can sell is a deterministic regression gate on the evidence-backed levers, with a plain statement of what the score does and does not measure. Given the developer audience's reflex to attack unverifiable claims (a "Rated 5/5 by 100+ SEOs" badge drew "is this just marketing lies?") and praise verifiable ones ([HN 48020249](https://news.ycombinator.com/item?id=48020249)), that honesty is a moat rather than a concession.

The same evidence says which checks to add. Next.js streaming metadata is the most reproducible SEO failure in developer write-ups: a canonical that "literally doesn't exist yet" when Googlebot reads the initial response produced "Duplicate without user-selected canonical" and "a flat line. Zero impressions" for weeks ([dev.to](https://dev.to/federico_sciuca/the-nextjs-seo-bug-that-made-google-ignore-my-entire-site-and-how-i-found-it-2mg0)), the issue tracker has four separate reports with 12 to 19 upvotes each ([vercel/next.js#80868](https://github.com/vercel/next.js/issues/80868)), and a September 2026 issue reports "AI search crawlers and TelegramBot miss streaming metadata in Edge SSR" ([vercel/next.js#98748](https://github.com/vercel/next.js/issues/98748)). That failure is invisible to curl and to a full-render crawler; it needs a fetch as Googlebot and as the AI search bots that reads the initial HTML before streaming completes, which is exactly RankCLI's no-browser architecture. Likewise "Google Indexed 258 of My 406 Pages" was diagnosed by crawling with JavaScript disabled and building a link graph, because "The content was server-rendered. The navigation was not" ([dev.to](https://dev.to/kimusta/google-indexed-258-of-my-406-pages-the-sitemap-was-never-the-problem-3dhh)); a JS-off crawl-depth and orphan check is what those authors wished they had.

## Position RankCLI as the gate that fails the build and opens the fix

The uncontested position is the left side of the pipeline. Every leader starts measuring after the site is live and sends findings to a marketer's dashboard; no leader runs on a preview URL, fails a build, or lands a change in the repository. The positioning statement that follows from the evidence is: RankCLI is the SEO and AI-search readiness gate for CI. It runs before deploy on a preview URL or a local build, fails the build on the regressions that cost weeks of traffic (a stray noindex, a canonical pointing at staging, a page answering 5xx, a blocked OAI-SearchBot or Claude-SearchBot, a soft-404 llms.txt or sitemap, navigation only reachable through JavaScript, metadata that streams in after the crawler has left), and opens the pull request that fixes them in the framework's idiom. The existing taglines ("Ship code, get ranked", "SEO meets CI/CD") already say this; the product surfaces and the first-run output do not yet.

Three naming decisions follow. Do not lead with "GEO" as the product noun: it collides with GeoReady's own name and category keyword, developers mock it ("The marketing industry is currently calling SEO for chatbots 'GEO'. I hope it doesn't stick") ([HN 47127532](https://news.ycombinator.com/item?id=47127532)), and Google has defined it away as "still SEO". Use "AI-search readiness" alongside "SEO", which matches both Google's and Bing's framing and at least six npm descriptions already in use. Do not put "SEO" in a Hacker News title: no Show HN containing "SEO" has exceeded 8 points since 2024, while "Removing Next.js Got My Blog to 100 on Every Lighthouse Category" reached 198 points in October 2026 and Jampack, framed as Core Web Vitals, reached 328 ([HN Algolia](https://hn.algolia.com/api/v1/search?query=Show%20HN%20SEO&tags=story); [HN 50237712](https://news.ycombinator.com/item?id=50237712); [HN 39816836](https://news.ycombinator.com/item?id=39816836)). And do not claim prompt tracking, share of voice or sentiment; name a tracker (Otterly at $29, or the free BYOK Lettertrace) as the after-deploy complement and claim only the diagnostic layer, "why this page is or is not citable", plus the regression gate.

Two scope statements make the position defensible. Against Google, match Lighthouse's Agentic Browsing semantics for llms.txt exactly and extend to what Lighthouse does not check: bot-class access at the edge, freshness signals, and answer-shaped content. Against the browser-based rivals, keep "zero-browser, under 15 seconds, nothing leaves your machine" as named features; the MCP registry description already says "no signup, nothing leaves your machine" ([MCP registry](https://registry.modelcontextprotocol.io/v0/servers?search=rankcli)), and developers who tried Lighthouse in CI complained about the four minutes it added. State the trade-off plainly: SPAs that render content only in the browser are reported as such, not scored.

On pricing, the shape is right and the hook is wrong. Developers in this category ask for usage pricing ("would love to see pricing where I can just buy credits instead of paying monthly") and call $79/mo AI-visibility tools "something you can build in an afternoon with Haiku" ([HN 48020249](https://news.ycombinator.com/item?id=48020249); [dev.to](https://dev.to/dannwaneri/the-llm-visibility-tools-cost-79month-mine-is-open-source-29hb)). The two closest comparables price entry at $15 (Spronta SEO Radar, 5,000 pages, "scheduled scans, comparisons and alerts") and $19 (squirrelscan Pro, whose paid pitch is "scheduled audits email you when a link breaks"), with teams at $29 per seat ([Spronta pricing](https://www.spronta.com/pricing/); [squirrelscan pricing](https://squirrelscan.com/pricing)), and Checkly's "monitoring as code" sells a free Hobby tier and a $64/mo Team tier on the same logic ([Checkly](https://www.checklyhq.com/pricing/)). RankCLI's Free tier ("1 site audited weekly") matches squirrelscan's free tier almost exactly, so cadence cannot be the free-tier differentiator; the fix PR can. Since every RankCLI plan already runs all 280 checks, the paid value is monitoring and alerts (a scheduled run that tells you when a noindex ships) and usage, not more checks; the $9 Solo price is below the comparables and can hold, while the "Pro" message should be "audit on every push, PR per regression" rather than site counts no developer asked for.

## The plan: five product changes and six distribution moves, in priority order

### Product

The first change is to publish the CLI source. Of the 45 highest-scoring developer-tool Show HNs above 150 points since 2025, **35 carry "open source" in the title**, and "Is it open source?" is the first question in threads ([HN Algolia](https://hn.algolia.com/api/v1/search?tags=show_hn&numericFilters=created_at_i%3E1735689600,points%3E150)); every 2026 Astro SEO-audit integration that out-downloads RankCLI has a public repository linked from npm ([astro.build](https://astro.build/integrations/?search=seo)); and the Claude Code open-source request collected 74 reactions before being closed ([claude-code#249](https://api.github.com/repos/anthropics/claude-code/issues/249)). The evidence does not say openness produces revenue, it says openness produces distribution: Knip does 72.76M downloads a month on about $200 a month in sponsorship ([npm API](https://api.npmjs.org/downloads/point/last-month/knip); [knip.dev](https://knip.dev/sponsors)), and the model that pairs an open client with a closed hosted backend reached 63.9k stars for Context7 ([GitHub API](https://api.github.com/repos/upstash/context7)). RankCLI's npm packages are already MIT, so nothing is protected by keeping the repository private. Concretely: open the CLI and agent-runtime in one public repository, add `repository` fields to every npm package, fix the plugins' 404 repository link, point the homepage CTA and the changelog at it, and let GitHub's "Used by" graph start counting. Keep the hosted audit worker, GitHub App and dashboard closed.

The second change is to repair the first run so the second look confirms the first. Remove the top-10 cap (print all findings grouped by severity, with `--limit` as the opt-in), collapse duplicate codes to one code per condition (viewport, llms.txt, schema, H1, CSR, internal links, Bing verification, IndexNow, sitemap, social proof), delete the checks that fire regardless of content (`BING_PLACES_MISSING`, `REVIEW_NO_VIDEO`, `AMP_MISSING`, `NO_YOUTUBE_PRESENCE`, `NO_EMBEDDED_SOCIAL`, `COMMERCIAL_NO_CTA` on non-commercial pages) and any check whose claim the tool cannot support (`CONTENT_AUTHORITY_IMBALANCE` without backlink data, `BING_NOT_VERIFIED` as a warning, `NEW_SITE_STRATEGY` from a wrong age), raise the 100 KB `HTML_TOO_LARGE` threshold, exempt brand names from `KEYWORD_STUFFING`, and make `audit`, `apply` and `fix` share one engine and one score. Follow `meta refresh` on the root document. Make `audit` read `rankcli.config.json`. Hide `report`, `watch` and `competitors` until they work. Suppress the login box when `-o json`, `--fail-on` or `--min-score` is set, and replace the raw Node error with a one-line message. Add a timestamp, CLI version, per-page breakdown and list of passed checks to the JSON document. Then reconcile the words: the npm README should say free forever, 32 frameworks, 15 tools and show the real MCP tool list; the homepage step one should not say "log in"; the docs should document the four exit codes and drop the nonexistent "local project" and `-b` options. Re-run docs.astro.build after the meta-refresh fix and retire the 57 from VERIFIED-NUMBERS.md.

The third change is to align the AI-readiness checks with the citation evidence, which is also the best content story the product has. Split bot access into three classes (training: GPTBot, ClaudeBot, CCBot; search: OAI-SearchBot, Claude-SearchBot, PerplexityBot, Googlebot, Bingbot; user-triggered: ChatGPT-User, Claude-User) and report each from robots.txt and from a live fetch as that user agent with the HTTP status, so a Cloudflare or WAF block shows as the error it is; squirrelscan already exits 3 on a challenge page, which is the right idea ([squirrelscan audit docs](https://docs.squirrelscan.com/cli/audit.md)). Verify llms.txt and sitemap by content type and content, report llms.txt as a notice framed for agents and docs with Lighthouse's exact criteria, and add a generator for docs sites (where the demand is) rather than a warning for marketing sites. Move schema into the technical-SEO score. Add freshness (visible dates, sitemap `lastmod` consistency, IndexNow presence) and answer-first structure (direct answer in the first block, statistics with sources, tables) as the AI content checks, citing the studies in the `howToFix` text. Add a JS-off link-graph pass that reports crawl depth and orphans, and a fetch-as-Googlebot initial-HTML pass that catches Next.js streaming metadata and `<head>` tags rendered into `<body>`. Finally, write the scoring note in the docs and the JSON: the AI Readiness score measures hygiene on evidence-backed levers; it does not predict citations, and no published study shows that any score does.

The fourth change is the CI plumbing, which closes the gap with every rival at once because all of it sits on the existing JSON report. Ship a config file that `audit` reads (URL, pages, ignore rules by code and URL pattern, per-category budgets, headers), `--baseline <file>` plus `rankcli diff` so an existing site can adopt the gate without first fixing every historical finding and only new regressions trip `--fail-on`, per-category gates in the squirrelscan style (`--fail-on score:aiReadiness<70`), `-o sarif` for GitHub Code Scanning and `-o junit` for test reporters, `--header` and `--cookie` for protected previews, sitemap-seeded discovery as the default crawl strategy, and `--dir dist/` so the build output can be audited without a server (the framework plugins already parse built HTML). Update the Action to post one check-run with annotations and one PR comment that is updated in place; Dependabot's 40 million PRs a year show the PR surface is the loop that scales, and the 647-point "Turn Dependabot off" thread shows it reverses when the bot is noisy ([Octoverse](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/); [HN 47094192](https://news.ycombinator.com/item?id=47094192)). Comment only on regressions against the baseline, never on every deploy. Have `rankcli setup --github-action` write a workflow that uses the published Action instead of a hand-rolled `npm install -g`.

The fifth change is the agent and framework surfaces. Rename the skills to task names that do not collide: the generic `seo-audit` playbook from marketingskills has **240,611 installs** and RankCLI's identically named skill has one, while squirrelscan's task-named `audit-website` has 74,498 against 3,131 for the one named after the product ([skills.sh API](https://www.skills.sh/api/search?q=seo); [skills.sh](https://www.skills.sh/squirrelscan/skills)). Names like `check-site-before-deploy`, `fix-seo-regressions` and `is-my-site-blocked-from-ai-search` describe intents an agent user types. Add `--format llm` as squirrelscan and SEOmator do, make the hosted free endpoint's tool list match the local server's, and keep the CLI README's MCP section in sync with `tools/list`. Describe the framework plugins honestly as "SEO lint, sitemap and robots for your build" or make them run the real engine post-build; a developer who installs `astro-rankcli` expecting 280 checks gets seven ([astro-rankcli](https://www.npmjs.com/package/astro-rankcli)). Make Astro the lead plugin, because that directory is the one place where comparable 2026 entrants with no audience reached 1.6K to 7K downloads a month.

### Distribution

List the Action on the GitHub Marketplace this week; `action.yml` already carries the required branding block, seven rivals are listed, and `@druedaro/seo-lint` reached 565 downloads a week within 27 days of creation with one star, largely by being one of three Actions returned for "geo seo" ([seo-lint listing](https://github.com/marketplace/actions/seo-lint); [npm API](https://api.npmjs.org/downloads/point/last-week/@druedaro/seo-lint)). The official MCP registry entry already exists; keep it current with each release.

Treat skills.sh as the primary agent channel and understand its mechanism. It is the only directory where an SEO-audit capability has demonstrably moved six-figure installs in 2026, but the installs came from creators with audiences publishing skill repos (Corey Haines, Matt Pocock, Addy Osmani), not from listing ([skills.sh](https://www.skills.sh/)). The marketingskills README funds itself by listing "Verified Partners" that 240,000 installers see, with an AEO tool already among them ([marketingskills](https://github.com/coreyhaines31/marketingskills)); a partner slot there, or a contributed RankCLI-backed check in Addy Osmani's `web-quality-skills` (52,693 installs of its `seo` skill), is worth more than any launch post. Vercel Marketplace integrations now auto-install the provider's skills from skills.sh ([Vercel changelog](https://vercel.com/changelog/vercel-marketplace-agent-skills)), so the hosted product should become a Vercel integration that audits preview deployments, which turns every install into a skill install.

Use framework directories as the cheapest measurable channel. `astro-rankcli` is already listed as "new" at 20 weekly downloads, while `@nuasite/checks` (created March 2026) shows 7,015 downloads a month and `astro-seo-enforcer` (August 2026, "fails the build when it detects SEO violations") 1,681 ([astro.build](https://astro.build/integrations/?search=seo)). Nuxt's SEO module does 171,185 downloads a week, which is where a `nuxt-rankcli` module would sit ([npm API](https://api.npmjs.org/downloads/point/last-week/@nuxtjs/seo)). The pattern across every tool with more than a million downloads a month is the same: adoption came from being a default somewhere (a template, a framework integration, an agent client), never from a post; Knip took 2.5 years to reach 10,000 projects ([knip.dev](https://knip.dev/blog)), Playwright MCP went from 1.0M to 29.3M monthly downloads while its own HN post scored 6 points ([npm range API](https://api.npmjs.org/downloads/range/2025-07-01:2026-10-28/@playwright/mcp); [HN 43465931](https://news.ycombinator.com/item?id=43465931)), and Checkly's CLI has 97 stars and 1.1M downloads a month ([GitHub API](https://api.github.com/repos/checkly/checkly-cli)).

Make data content the top of the funnel, in Socket's pattern. Socket's installable artefact is constant and its spikes come from timely posts about concrete failures; its Shai-Hulud write-up drew 1,233 HN points and "Within 24 hours, more than 2,000 organizations had onboarded" after the Axios compromise ([Socket](https://socket.dev/blog/socket-raises-60m-series-c-press-release); [HN 45260741](https://news.ycombinator.com/item?id=45260741)). The SEO stories that reach the hundreds on HN are grievances about the AI and Google shift (AI Overviews 758 points, Perplexity's stealth crawlers 1,315, "I'm losing the SEO battle for my own open source project" 533) ([HN 47232158](https://news.ycombinator.com/item?id=47232158)), and TLDR Dev featured a 17-minute log study of what AI bots actually fetched ([TLDR Dev](https://tldr.tech/dev/2026-10-20)). RankCLI's equivalent is a nightly re-audit of a public corpus, published as a dataset with the open-source repo attached (geolint re-audits eight sites nightly; geo-score runs a 324-site leaderboard; RankCLI has none), producing titles such as "N of the top 1,000 Next.js sites block Claude's search crawler" or "N docs sites serve their llms.txt as an HTML page", never containing the word SEO. Expect a front page to be a credibility and backlink event rather than a signup event (the one measured in-window ratio is about 1,000 visitors to 3 signups) ([dev.to](https://dev.to/ddltodata/how-my-first-hacker-news-launch-went-and-what-i-did-about-it-40k9)), and use the sanctioned retries: a repost after a year, and an email to the moderators for the second-chance pool ([HN 26998308](https://news.ycombinator.com/item?id=26998308)).

Ship weekly with prose changelogs. squirrelscan's 29 releases in 16 days and GeoReady's 90 releases are each indexed pages and each a reason for an existing user to update; RankCLI's undated changelog page and 15-day silence are the opposite signal. Date the changelog, link each entry to the public repo's release, and make the release note the one artefact that goes to npm, GitHub, the Marketplace, the MCP registry and the skills repo in the same hour.

Last, prepare the analyst surface without depending on it. Create the G2 listing in "SEO Tools" and "Answer Engine Optimization", collect the ten approved recent reviews a Grid placement needs, and aim for High Performer rather than Leader, since Market Presence weights employee counts and review volume that favour incumbents ([G2 methodology](https://documentation.g2.com/docs/research-scoring-methodologies)). A "Developer SEO" category request needs ten competing products, and the 2026 entrants supply the names, but it would start without a Grid.

The things not to do are as evidence-backed as the things to do. Do not sell the score as a citation predictor (GeoReady's null result will be cited back). Do not resell prompt tracking; it is the leaders' unit of sale and puts RankCLI on the wrong G2 criteria. Do not chase stars with promotion: Ryze's 7,912 stars arrived in daily spikes of +400 on a repo with 16 commits and no merged PRs, which the trend data suggests was paid or coordinated ([trendshift.io](https://trendshift.io/repositories/199616)). Do not treat README badges as a growth lever; no 2024 to 2026 source quantifies badge referrals for any tool. And do not comment on every deploy.

## Conclusion

The research reframes RankCLI's problem from "not enough people know about it" to "the people who find it are not yet given a reason to trust it", and reframes the category from "GEO, where Profound leads" to "the pre-deploy gate, where nobody leads yet". Those two reframings connect: the leaders' entire economic model (daily prompt runs sold to marketers, optimisation delivered as hosted overlays) structurally prevents them from occupying the left side of the pipeline, and the incumbent crawlers' per-user desktop licences and quote-only CI products prevent them too. What is arriving instead is a stream of single-author CLIs and Lumar's 19-check scout, which means the window is measured in months, and the measure of winning it is weekly downloads, skill installs and Marketplace presence, where squirrelscan's 3,784 a week is the number to pass.

The least obvious implication is that honesty is the differentiator the evidence supports best. No readiness score predicts citations, llms.txt is not read by any answer engine, schema moves nothing measurable, and developers reward tools that say so while attacking tools that do not. A product that opens its source, prints every finding, uses one code per condition, tests crawler access the way the failure actually happens (at the edge, as the bot), and states in its own output what its number does and does not mean would be the only one in the category doing all five. RankCLI already has the hard part, the fix PR in the framework's idiom; the plan above is mostly about letting a sceptical developer get far enough to see it.
